# 2-Player Real-Time LAN Co-op Plan

## Current Foundation (Implemented)
- **LAN HTTP + WebSocket Server** (`server.js`): Binds to `0.0.0.0:3000`, exposes `/api/lan-info` for one-click LAN URL sharing, and runs a `/ws` WebSocket room relay.
- **Room Lifecycle**: `create_room` (4-letter code), `join_room` (max 2 divers), `set_ready`, `start_dive`, automatic host promotion on disconnect.
- **20 Hz Peer State Sync** (`public/js/net/lanClient.js`): Streams diver pose (`x`, `y`, `vx`, `vy`, `angle`), `activeGasId`, `torchOn`, `alive`, and checkpoint hits, with linear interpolation on the peer diver renderer.

## Phase 2: Full 2-Player Co-op Mechanics (Planned)
1. **Out-of-Air (OOA) Buddy Gas Sharing**:
   - When Diver A runs low/out of gas, approaching within `2.5m` of Diver B unlocks a **SHARE OCTO** button on the Dive Computer HUD.
   - Diver B's selected tank feeds both divers (`SAC_A + SAC_B`), visually drawing a yellow long-hose regulator between the two divers.
2. **Buddy Line & Light Signals**:
   - Tapping the torch button sends light-signal sweeps ("OK", "Attention", "Problem") visible in the peer's torch cone.
   - Silt clouds generated by Lead Diver are broadcast (`silt_burst` events) so Diver 2 must navigate through reduced visibility behind Diver 1.
3. **Team Decompression & Objective Sync**:
   - Both divers must tag checkpoints and clear their individual decompression ceilings before surfacing at Cenote Beta for a team mission pass.
4. **Network Resilience**:
   - Client-side dead reckoning + timestamped snapshot buffer (100ms jitter buffer) to keep peer motion silky smooth on mobile Wi-Fi.
